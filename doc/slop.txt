==============================================================================
1. INTRODUCTION                                                   *slop-intro*

slop.nvim is a single plugin made of small modules. Each module lives in
`lua/slop/modules/<name>/` and loads lazily: at startup only a tiny manifest
is read. Requires Neovim 0.12+. No dependencies.

==============================================================================
2. INSTALL                                                      *slop-install*

lazy.nvim: >lua
    return { "hexdigest123/slop.nvim" }
<
The shipped `lazy.lua` makes lazy call `require("slop").setup({})`.

vim.pack: >lua
    vim.pack.add({ "https://github.com/hexdigest123/slop.nvim" })
    require("slop").setup({})   -- optional
<
There is no need to lazy-load slop itself. If you do (e.g. lazy.nvim
`event = "VeryLazy"`), the modules that load when a file is read (cloak,
todo, context) are loaded right away for the files already open, and the
modules of a filetype (rest, commit) for the buffers that already have it.
The same goes for a module that a later `setup()` call enables.

==============================================================================
3. CONFIGURATION                                  *slop-config* *slop.setup()*

`require("slop").setup(opts)` only stores options; it may be called any
number of times, before or after the plugin is loaded (each call replaces
the options of the previous one). Options can also be given as `vim.g.slop`
(a table or a function returning one, `modules` included).

Precedence: defaults < `vim.g.slop` < `setup(opts)`; `:Slop modules
enable|disable` wins over both for the rest of the session.

Core options: >lua
    {
      ui      = { border = "rounded", spinner = "dots", picker = "auto" },
      log     = { level = "warn", max_entries = 2000 },
      project = { root_markers = { ".git" }, dir = ".nvim" },
      secrets = {
        block = { ".env*", "*.pem", "*.key", "*.p12", "*.pfx",
                  "*secret*", "*credential*", "*private-key*",
                  ".netrc", "_netrc", ".npmrc", ".pypirc",
                  ".git-credentials", ".kube/config", "*kubeconfig*",
                  "*service-account*.json",
                  "id_rsa", "id_dsa", "id_ecdsa", "id_ed25519" },
        placeholder = "<redacted>",
        agent_reads = "deny",
        detectors = true,
      },
    }
<
Options are merged into the defaults, except lists: a list you give
replaces the default one (to add a glob to `secrets.block`, list the
defaults too). `log.max_entries` is the number of messages `:Slop log`
keeps (an integer >= 1). `secrets.block` globs without a "/" match the file
name, the others match below any directory; a leading `~/` is your home
directory. `secrets.agent_reads`: "deny"
(default): ACP agents cannot read blocked files; "allow": slop's own
`fs/read_text_file` serves them to an agent, with every secret value
redacted (binary files, with NUL bytes, are still refused). Either way, a
permission request of an agent's own tool that touches a blocked file is
rejected (with it, the agent would read the file itself, unredacted), and
agents can never edit, move or delete a blocked file (see
|slop-edit-agents|). `secrets.detectors = false` turns the built-in token
detectors off (|slop-secrets|).

Every module is configured under its name, e.g. `opts.term = { ... }`.
`opts.<module> = false` (or `{ enabled = false }`) disables it; a later
`setup()` that disables a loaded module unloads it, like `:Slop modules
disable`.
User modules: `opts.modules = { mine = require("my.slop_module") }`, a table
of name = spec (the spec is used as it is, see |slop-module|).

AI providers (service `ai`) read their API key from `<SERVICE>_API_KEY`
(e.g. `MISTRAL_API_KEY`). Override per provider with `api_key`, either the
NAME of another environment variable or a function returning the key: >lua
    ai = { providers = { codestral = { api_key = "MISTRAL_API_KEY_NVIM" } } }
<
A string `api_key` is always a variable name: a key pasted there is
rejected as an invalid option (and never echoed). The result of an
`api_key` function is cached for 5 minutes, so a password manager is not
asked on every keystroke.

Invalid options are reported with their path (e.g. `term.layout`) and the
type of their value, never the value itself; unknown options are reported
as typos. A module with invalid options does not load; when it was to load
because a file is being read, the message comes right after the read (the
file is always read). See |slop-health|.

==============================================================================
4. COMMANDS                                                  *:Slop* *slop-commands*

:[range]Slop {module} [subcommand] [args]
        Run a module subcommand (the module loads on first use).
:Slop health                                         Run `:checkhealth slop`.
:Slop log [clear]                        Open the log (`q` closes) or clear it.
:Slop modules [enable|disable {name}]     List modules or toggle one.

==============================================================================
5. KEYMAPS                                                      *slop-keymaps*

Every module action is a `<Plug>(slop-<module>-<action>)` mapping: global
keys, keys local to a buffer or filetype (e.g. a result window) and the
insert-mode keys that fall through alike. Default keys map to those, only
when the key is free and you have not mapped the `<Plug>` yourself. Change
or disable a default key in the module's `keymaps` table: >lua
    require("slop").setup({ term = { keymaps = { toggle = "<C-\\>", split = false } } })
<
The `<Plug>` mappings of slop's startup keys exist right away; the others
(buffer-local and filetype keys, and the keys of modules without a startup
entry, see |slop-module|) are created when the module first loads. The
`<Plug>` of a key that falls through does nothing when there is nothing to
act on. While a module is disabled (`:Slop modules disable`), its mappings
only say so (a key that falls through passes the key on).

A key that falls through (nothing to accept, cursor not in a hunk, ...)
behaves as if slop had not mapped it: the previous mapping or the native
key runs, with the count you typed. When other mappings start with that
key (e.g. Neovim's `grn` behind the diff review's `gr`), the keys you type
next are matched against them first (<Esc> cancels).

slop never maps <Tab> by default.

==============================================================================
6. HIGHLIGHTS                                                *slop-highlights*

All groups are defined with `default = true` (your colorscheme wins):
SlopNormal SlopBorder SlopTitle SlopFooter SlopGhost SlopDim SlopSpinner
SlopDiffAdd SlopDiffDelete SlopDiffChange SlopDiffText SlopMatch SlopSelected
SlopRedacted, plus module groups named `Slop<Module><Thing>`.

==============================================================================
7. EVENTS                                                        *slop-events*

slop fires `User` autocmds named `Slop<Module><Event>` with `ev.data`, e.g.
`SlopTermOpen`. Core events: `SlopConfigChanged`, `SlopModuleLoaded`
`{ name }`, `SlopModuleDisabled` `{ name }`. An error in your handler does
not interrupt slop. `SlopModuleLoaded` of a module that loads because a
file is being read fires right after that read.

==============================================================================
8. PROJECT FOLDER                                               *slop-project*

The project root is found with `vim.fs.root()` and `project.root_markers`,
falling back to the current directory. `<root>/.nvim/` holds project files:
hand-written ones (`commit.md`, `rules.md`) and generated state in
`<root>/.nvim/state/` (a `.nvim/.gitignore` containing `state/` is written
when that folder is first created).

==============================================================================
9. SECRETS                                                      *slop-secrets*

Text sent to an AI provider or agent always passes through slop's redaction.
Hiding/revealing cloaks on screen never turns redaction off.

- Files matching `secrets.block` (|slop-config|) are never sent.
- A file reached through a symlink is also matched by its target's path:
  `app.conf -> .env` is blocked like `.env`, and the target's cloak rules
  redact it.
- Values found by secrets providers (|slop-cloak| rules) are replaced by
  `secrets.placeholder` ("<redacted>"). A provider that errors fails
  closed: every line it was given is redacted.
- Private keys (PEM, OpenSSH, PGP: `-----BEGIN ... PRIVATE KEY-----`,
  `... PRIVATE KEY BLOCK-----`) are redacted wherever the marker is in a
  line, also one-line escaped keys (`"-----BEGIN PRIVATE KEY-----\n..."` in
  e.g. a GCP service-account JSON) and text that starts inside a key (slop
  looks back for the BEGIN line). A mere mention of the marker in code does
  not redact the rest of the file.
- Built-in token detectors, for AI text only (not masked on screen), on
  unless `secrets.detectors = false`:
    AWS access key ids       `AKIA` / `ASIA` + 16 characters
    GitHub tokens            `ghp_` `gho_` `ghu_` `ghs_` `ghr_` + 36 or more,
                             `github_pat_` + 22 or more
    GitLab tokens            `glpat-` + 20 or more
    Slack tokens             `xoxa-` `xoxb-` `xoxp-` `xoxr-` `xoxs-`
                             + 10 or more
    OpenAI/Anthropic style   `sk-` (also `sk-proj-`, `sk-ant-`) + 20 or more
    Stripe keys              `sk_live_` `rk_live_` `sk_test_` `rk_test_`
                             + 16 or more
    Google API keys          `AIza` + 35 characters
    JWTs                     three base64url parts: `eyJ...` `.eyJ...` `.sig`
    URL credentials          `scheme://user:PASSWORD@`: the password only
  A token counts only on its own (not inside a longer word).

==============================================================================
10. HEALTH                                                       *slop-health*

`:checkhealth slop` checks Neovim, `git`/`curl`, the configuration of every
namespace (also of a disabled module you configured: a mistake may be what
disables it), each enabled module and service (e.g. which API key
environment variable is used and whether it is set). Option values and
logged messages are never printed.

==============================================================================
11. WRITING A MODULE                                             *slop-module*

Add `lua/slop/modules/<name>/init.lua` returning a spec: >lua
    return {
      name = "mine",
      description = "what it does",
      defaults = { enabled = true, keymaps = { run = "<leader>xm" } },
      schema = function(cfg, check) check("keymaps", cfg.keymaps, "table") end,
      setup = function(cfg) end,          -- once, on first use
      commands = { run = { impl = function(args, cmd) end } },
      keymaps = { run = { mode = "n", desc = "run mine", rhs = function() end } },
      health = function() vim.health.ok("fine") end,
      api = {},                           -- require("slop").mine
    }
<
See `lua/slop/modules/hello/` for a complete example.

A module found on the 'runtimepath' loads on first use (`:Slop mine ...`,
`require("slop").mine`). Its keymaps, default keys and `<Plug>` mappings
are created when it loads, not at startup. To have them (and load events)
from startup, register it as a user module (`opts.modules`, also in
`vim.g.slop`) with a `manifest`: >lua
    -- lua/my/slop_module.lua: the spec above, plus
    manifest = {
      keys = { run = { mode = "n", lhs = "<leader>xm", desc = "run mine" } },
      events = { "BufReadPost" }, -- optional: also load on this event
    },
    -- init.lua
    require("slop").setup({ modules = { mine = require("my.slop_module") } })
<
Keep `manifest.keys.<action>.lhs` equal to `defaults.keymaps.<action>`. A
broken `manifest` (an unknown event, a bad mode) is reported and skipped.
The event that loads a module is replayed into its augroup: create its
autocmds in `require("slop.core.util").augroup("mine")`. A handler that
fails on the replayed event is reported; it never stops the command that
fired the event (the file is still read).
